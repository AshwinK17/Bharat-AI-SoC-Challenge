# Running Xaverix on the phone

No laptop, no `adb`, no Kotlin, no Android build. Everything runs on the phone:
**ExecuServe** hosts Llama through ExecuTorch, and **Termux** runs the Python
app. They talk to each other over loopback.

```
┌─────────────────────── your Android phone ───────────────────────┐
│                                                                  │
│  ExecuServe (app)                      Termux                    │
│  ├─ Llama 3.2 1B Instruct              ├─ python + numpy + PIL   │
│  ├─ INT4 / XNNPACK .pte                ├─ server.py :8000        │
│  └─ ExecuTorch runtime                 └─ vision + guard + KB    │
│          ▲                                      │                │
│          └──── http://127.0.0.1:8080/v1 ────────┘                │
│                   (loopback only)                                │
│                                            Chrome → :8000        │
└──────────────────────────────────────────────────────────────────┘
```

Total time: about 25 minutes. Connect the charger first; generation is
CPU-intensive and drains the battery quickly.

---

## Part 1 — Llama on the phone (about 10 minutes)

1. Install **ExecuServe** from Google Play.
2. Open **Library → Browse catalog** and download **Llama 3.2 1B Instruct**.
   Choose the **CPU (XNNPACK)** variant with the **4k context window** —
   roughly 917 MB, needing about 1.4 GB free.
   - CPU (XNNPACK) is the Arm CPU path the brief asks for. The Vulkan GPU
     entries are not.
   - 4k is ample: our prompt is about 750 characters and the answer is capped
     at 200 tokens.
   - Stay on Wi-Fi for the download.
3. Grant the **notification** permission when asked. Without it Android may
   silently kill the server while you are in Termux.
4. Leave **"Who can connect" set to "This phone"**. Termux is on the same
   device, so loopback is all that is needed, and it keeps the offline story
   intact.
5. Go to the **Hosting** tab, select the model, and tap **Start hosting**.
6. Copy the **API key** shown under Connect. You need the full key, not the
   shortened display form.
7. Optional but good for the video: in the **Chat** tab, ask
   *"In one sentence: what is early blight of tomato?"*

> The answer to step 7 is likely to be factually wrong: during evaluation the
> model attributed early blight to a non-existent bacterial genus. This is
> expected from a model of this size, and is the reason Xaverix constrains
> generation to restating knowledge-base facts and verifies the result.

Leave ExecuServe running. Do not swipe it away.

## Part 2 — the app in Termux (about 10 minutes)

Install **Termux from F-Droid**, not the Play Store (the Play build is
outdated). Then, one command at a time:

```bash
termux-setup-storage          # tap Allow on the popup
pkg update -y && pkg install -y python python-numpy python-pillow unzip
```

Do **not** run `pip install psutil`. It needs a compiler and will fail;
Xaverix reads memory from `/proc/self/status` instead and does not need it.

Unzip the project:

```bash
cd ~ && unzip -o ~/storage/downloads/xaverix-submission-*.zip && cd xaverix
ls
```

If unzip cannot find the file:

```bash
ls ~/storage/downloads | grep -i xaverix
```

The trained model ships inside the zip, so **there is nothing to train on the
phone**. Confirm it arrived:

```bash
ls -la models/leaf_health.npz
```

Start the app, pasting the ExecuServe key in place of `PASTEKEY`:

```bash
XAVERIX_LLM=1 \
XAVERIX_LLM_URL=http://127.0.0.1:8080/v1 \
XAVERIX_LLM_KEY=PASTEKEY \
XAVERIX_LLM_MODEL=llama-3.2-1b-instruct \
TARGET_DEVICE="<your phone model> (Arm64 Android, Termux)" \
python server.py --port 8000
```

The startup banner tells you whether Llama was found. Then open
**http://localhost:8000** in Chrome on the phone.

## Part 3 — confirm Llama is really being used (2 minutes)

In a second Termux session (swipe in from the left edge → **New session**):

```bash
cd ~/xaverix
curl -s localhost:8000/api/config | grep -o '"usable":[^,]*'
```

You want `"usable": true`. Then, in the browser:

1. Pick a stored sample — use **`infected_04.png`** or similar, **not** your
   own photo (see the warning below).
2. Tap **Analyse**. The first Llama call can take 10-60 seconds while the
   model loads; the UI says so rather than appearing to hang. If it is still
   cold, you get the knowledge-base advisory labelled *"Llama is still
   loading"* and the next attempt will use Llama.
3. The provenance chip should turn green:
   **"Generated by Llama 3.2 1B · ExecuTorch on-device (grounded)"**

If it instead reads *"rejected by grounding guard"*, that is also a correct
outcome: expand the guard report to see which rule fired.

> **Use the bundled samples, not your own leaf photographs.** The classifier is
> trained on procedurally generated imagery and is not valid on real field
> photographs. `ood_lined_paper.png` demonstrates the abstention path.

## Part 4 — real Arm measurements for the report (5 minutes)

```bash
cd ~/xaverix
TARGET_DEVICE="<your phone model> (Arm64 Android, Termux)" \
  python scripts/benchmark.py --iterations 25
cat results/benchmark.json
```

`TARGET_DEVICE` is required; without it the figures are labelled
`"unspecified"` rather than attributed to a development machine. Add `--llm` to
also time one grounded advisory.

The resulting `benchmark.json` provides the Arm column of the technical
report (§10.2).

## Part 5 — prove it is offline

```bash
curl -s localhost:8000/api/offline-proof
```

Expect `"blocked": true`, with `api.openai.com`, `8.8.8.8` and a DNS lookup of
`huggingface.co` all blocked, and `127.0.0.1:8000` still `allowed` — which is
what lets ExecuServe keep working.

For an end-to-end verification, enable aeroplane mode and repeat the flow. The
in-process guard constrains the Python process only; aeroplane mode verifies
the whole device, and `/api/offline-proof` records this in its `scope_note`.

## Troubleshooting

| symptom | cause and fix |
|---|---|
| `pip install psutil` fails | Expected. Skip it; it is not needed. |
| `"usable": false, "reason": "not_running"` | ExecuServe is not hosting. Reopen it and tap Start hosting. |
| `"reason": "bad_key"` | The API key is wrong or truncated. Copy the full key again. |
| `"reason": "bad_model"` | `XAVERIX_LLM_MODEL` does not match ExecuServe. Check the Hosting tab. |
| `"reason": "not_loopback"` | The URL is not `127.0.0.1`/`localhost`. Xaverix refuses non-loopback endpoints by design. |
| First analysis shows "Llama is still loading" | Normal on a cold 1B model. Try again in a minute. |
| Advisory keeps falling back after a retry | Expand the guard report in the UI; it names the rule that fired. |
| Server killed while in Termux | Grant ExecuServe notification permission; keep both apps in the recents list. |
| `ModuleNotFoundError: numpy` | `pkg install python-numpy` (not `pip install numpy`). |
| Model refuses to load, feature-version mismatch | `app/features.py` changed after training. Retrain on the dev machine: `python tools/train.py`. |
| Everything abstains as `no_leaf_detected` | Hold the camera 20-30 cm from one leaf so it fills the frame, in daylight, against a plain background. |
